# Reduced Go harness: 10,000 connections

Run date: 2026-09-05, Asia/Dhaka. Code base: `76a79e9` with the field/observer
remediation worktree; no load-harness changes after that checkpoint.

## Workload and result

Command: `scripts/load-test-10000.sh 10000`.

This endpoint is **ReducedMeshLoadHarnessService**, isolated from the secured
Android mesh contract and restricted to literal loopback. Each independent gRPC
connection opens a bidirectional stream, submits one reduced Protobuf record,
requires durable acknowledgement, then stays open with all other acknowledged
streams for five seconds. It does not measure encryption, origin verification,
signed Android acknowledgements, TLS or physical Nearby radios.

```text
connections_requested=10000
connections_acknowledged=10000
simultaneously_active=10000
ready_elapsed=1m10.46s
acknowledgements_per_second=141.93
ack_latency_p50=29.41s
ack_latency_p95=57.279s
ack_latency_max=1m0.433s
hold_duration=5s
server_peak_rss_kb=1188992
server_log_errors=0
```

The script exited successfully. All 10,000 streams were active together after
acknowledgement. Its temporary server and database were cleaned up by the script;
no field or demo database was reset.

## Environment and interpretation

- macOS 26.5, build 25F71; ARM64.
- 48 GiB host RAM; Go 1.27.1 darwin/arm64.
- One laptop, local loopback, fresh temporary Bolt storage.
- Other development processes were running; this was not an isolated benchmark lab.

Peak sampled server RSS was 1,188,992 KB (about 1.13 GiB). This is not handset RAM.
The 57.279-second p95 acknowledgement time is **capacity evidence only**, not an
acceptable emergency-response latency result. Batched durable writes and a sustained,
secured workload should be measured before making a production throughput claim.

The September 4 report remains historical. Its old NodeMeshService workload must
not be presented as secure Android interoperability; the endpoint now makes that
limitation explicit in its name and wire contract.
